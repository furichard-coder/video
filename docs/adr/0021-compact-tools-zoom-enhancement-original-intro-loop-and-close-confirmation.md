# ADR-0021：精簡工具列、放大畫質預設、原檔片頭循環與安全關閉

日期：2026-09-05  
狀態：Accepted

## 決定

1. 網格卡片主要工具保持在單列短按鈕；移動只顯示箭頭圖示，完整語意放在 `aria-label` 與 `title`。
2. 每個來源時間局部放大區段保存一個固定畫質預設：`BALANCED`（新區段建議預設）、`DETAIL`、`DENOISE` 或 `OFF`。這是可重現的 FFmpeg 消噪／銳利化參數，不是生成式超解析，也不得宣稱恢復遺失細節。
3. 局部放大保存後的片頭加入與 4K 片段輸出都是明確勾選動作。加入片頭須再指定順位並通過 3–22 秒、30 段及片頭總長 gate；4K 仍開啟輸出確認頁，不在勾選瞬間寫檔。
4. 片頭播放器先以 `source-media://asset/<asset-id>` 串流專案中已核對的唯讀原始影片，並以來源 IN／OUT 作循環邊界。只有內建 codec 不支援或讀取失敗時，使用者才主動切換至既有短代理。
5. `source-media` handler 只接受 64 位資產 ID，從 Main process 的 manifest 解析路徑，只讀串流且支援 byte range；Renderer 不提供任意路徑。
6. 一般視窗關閉先由 Main process 攔截，Renderer 顯示第二確認及短提示音；危險動作不是預設焦點。自動 smoke 與真正的 `before-quit` 流程直接通過，避免測試卡住。

## 理由

- 卡片在窄網格中不可因長字串被擠成直排，鍵盤與輔助工具仍需知道完整功能。
- 固定的溫和濾鏡比任意滑桿更容易重現與 QC；放大後的主觀改善必須和「不能創造原始細節」的限制一起呈現。
- 原檔區間循環可省掉每次選取片頭都等待代理的時間；明確 fallback 能兼顧 HEVC／特殊 MOV 等 Electron 未必能解碼的來源。
- 關閉確認是使用者明確要求，但不能妨礙自動驗證或讓誤觸的危險按鈕取得焦點。

## 相容與安全

- Schema 13 會把舊局部放大區段補為 `BALANCED`，不改寫來源媒體。
- 原始影片串流與 FFmpeg 濾鏡都只讀來源；輸出仍使用唯一 partial 與既有確認流程。
- 快速短代理仍是 App cache 衍生檔，絕不作正式輸出來源。
