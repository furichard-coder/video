# SceneryWalker 素材整理 App

這是剪接 App 的可驗收垂直切片。它負責選擇、排列及預覽影片／照片，並可產生串連或 Intro 預覽；不建立正式 Master、不做多軌 Timeline 剪輯，也不改寫或刪除來源檔。完成的正片或僅片頭預覽可由使用者確認後以 Chrome 拖放或 YouTube 官方 API 上傳到已核對的頻道；正片也可安全交接到 BiliBili／TikTok 官方投稿頁。只有使用者主動執行 AI 時，才會送出低解析故事板與故事背景；字幕的素材語音分析預設關閉，只有另行勾選才建立及送出短音訊。

目前版本：v0.80.0。

v0.80.0 完成一次唯讀、copy-on-write 的舊 checkpoint 恢復驗證：可讀取並重用 10 個 level-1 segments（合計約 67.547 GiB、媒體時間約 8976.718 秒），不重編這 10 段；Base Master 仍需重跑。跨 group xfade、ASS 字幕與浮水印使這 10 段不能直接以 `-c copy` 串接，最後 audio mux 則固定沿用 `-c:v copy`。舊版已刪除的 `base.partial.mkv` 不可恢復。

本次驗證採 15 秒 disk monitor 與 EMERGENCY safe pause。v0.79 classifier 命中 ENOSPC，但舊 raw stderr 未保存；曾記錄的 E: 144.45 GiB free 是刪除 partial 後的過時快照，UI 另曾顯示「建議再清 20 GiB」的錯誤提示，但沒有執行該清理，因此實際 E: 最低可用空間未知。基準回到既有 QSV GQ25：30 秒 bounded 測試的 SSIM 下降，故不採用該方案；本機 NVENC runtime 不支援，實際路徑為 QSV encode／CPU filter，慢速瓶頸約 0.10–0.115x。尚未跑完整長片，不宣稱已成功加速。

本版紀錄的 74 files／459 tests、typecheck、production build、audit 與 source／packaged smokes 均通過；若日後重跑，數字與結果仍以新產出的證據為準。

## v0.76 Render 效能與磁碟可靠性

- 實際 v0.75 失敗為 `-28 ENOSPC`：同一 `C:` 同時承擔中繼、partial、base master 與最終輸出，舊預估又以成品碼率低估 QSV GQ18 中繼。v0.76 改成逐磁碟峰值估算，納入中繼、同時 partial、音訊 TEMP、最終輸出、mux overhead 與 `max(20 GiB, remaining × 20%)` 安全保留。
- Render TEMP 可在轉檔頁指定其他可寫磁碟；預估、Runtime Monitor 與 checkpoint 都使用該實際路徑。執行中每 30 秒更新 TEMP／輸出磁碟，接近臨界值時停止排入新工作並在安全邊界保存 `PAUSED_DISK_SPACE`，不再等磁碟歸零才被動失敗。
- Resume 顯示前先核對完成片段的實體檔與大小，正式重用前再做 ffprobe／SHA-256。2026-09-18 的 05:57:13 舊工作只剩 JSON、實體片段已遺失，因此不能直接沿用；v0.76 會誠實標示並重建缺失片段。
- Normal／High Speed 從單一 FFmpeg 工作開始，只有前一波實測 throughput 提升且 CPU／GPU／RAM／Commit／SSD 有餘裕時才提高 concurrency；十輸入 1440p xfade 實測 2 jobs 只比 1 job 快約 4%，不再預先以兩個工作放大 OOM／ENOSPC 風險。
- 相容來源在 Normal 也會嘗試 QSV hardware decode；180 秒 4K→1440p 受控長測由 `171.72 s / 31.45 fps / 1.05x` 改善到 `162.33 s / 33.35 fps / 1.11x`，wall time 降低 5.47%。CPU filter 仍是主要瓶頸，沒有宣稱達到成熟 NLE 的專有 GPU composition 效能。
- 此機器的 NVENC runtime 因驅動 API 版本不足而不可用，實際高速路徑是 H.264 QSV。GQ22 雖節省約 38% 中繼空間，但品質指標低於 GQ18，因此正式預設維持 GQ18；沒有以降低畫質冒充效能改善。
- 中繼容器改用 MKV 以降低缺少 MP4 trailer 時整段無法恢復的風險；完整 FFmpeg integration 與額外 A/V timebase 驗證通過。跨批次 xfade、ASS 字幕與浮水印仍需 final picture pass，所以沒有不安全地強制全片 `-c copy`；只改 Audio 時仍沿用既有 video stream copy。

## v0.75 片頭／正片 Audio 分區與片段四軌開關

- 正片每個網格片段新增精簡的「原音／配音／BGM／SFX」四軌開關，舊專案與新素材四項預設全開。關閉配音或 BGM 不會靜音素材人聲；目前沒有獨立配音檔時，配音開關只保存為未來 voice track gate。
- 片頭與正片 UI、轉出摘要明確分區，但 Preview、Proxy、放大預覽與 Final 仍讀取同一份 canonical Audio Plan。片頭列改用細分隔線、留白與 compact controls，提高同畫面資訊密度。
- 「正片即將開始」提示音歸屬正片 SFX，預設開啟 0.65 秒，可設 0.10–3.00 秒或關閉。WebAudio 試聽與 FFmpeg 使用相同雙音頻率、延遲、增益與時長規格；提示音是 deterministic synthetic cue，不依賴品牌或外部授權素材。
- 原音 gate 只作用於該片段的 canonical timeline 範圍；Voice、BGM、SFX 各自獨立。BGM gate 關閉時採 25 ms 邊界平滑，歌曲播放頭仍繼續前進，下一片段重新開啟時不從 0 秒重播。Main-start cue 使用獨立的全域 Main gate，不會被任一片段 SFX gate 誤關。
- Picture/base master 的 signature 排除上述 post-audio 設定；只改四軌開關、正片提示音或全域 BGM 時，沿用已驗證畫面 master，Final post pass 固定 `-c:v copy`，只更新音訊 hash，不重編影片畫面。
- manifest 升級 schema 21；v0.74 的 per-instance SFX/BGM 設定完整保留，新增 gates 補為全開，正片提示音補為 ON／650 ms。

## v0.74 每次插入素材的 SFX／BGM 連續時間線

- 正片安插與片頭共用同一個「插入素材音訊」控制。每次照片出現預設啟用相機快門 SFX；每次影片預設關閉 SFX。同一來源重複使用時，每個實例可獨立設定並隨專案保存。
- SFX 與 BGM 是獨立勾選項，可單獨開啟、同時開啟或都關閉。BGM 以穩定 track ID 指定「不使用／第 1 首／第 2 首…」，SFX 不會中斷、重啟或靜音 BGM。
- 連續相鄰素材若使用同一首 BGM，會合併成一個連續播放範圍；照片、影片與沒有原音軌的影片都使用同一 Project Timeline。曲目改變或設為不使用時才在邊界切換／停止，並套用保守 Fade。
- BGM 比連續範圍短時會循環。一般範圍使用有限次數的真實 audio acrossfade；極端短素材為避免 filter graph 失控，會改用有界接點平滑並顯示警告。
- 總體預覽與片頭 proxy 預覽重用相同 Audio Plan，同一時點可同時聽到來源音、BGM 與 SFX，不重編 proxy 影片。Final 先保存不含 insertion audio 的 MKV+FLAC 畫面／基礎原音 master，再以一次 post pass 完成 mix 與 Original／Enhanced／Virtual 5.1；影片固定 `-c:v copy`。
- 每專案保留最近 1 份可重建 master，經 size、SHA-256、duration、codec 驗證後可跨 App 重開復用。轉檔頁 SSD 預估包含這份容量，也可由使用者確認後單獨清理；只改 SFX/BGM/DSP 不再重編影片。
- 「串接／轉出」確認區直接顯示 Final 使用的每筆插入實例與合併 BGM range：片頭／正片、照片／影片、開始、長度、原音軌、SFX 名稱、BGM 曲目／範圍／連續性／Loop／Fade。
- 舊專案自動遷移到 manifest schema 20：照片明確關閉快門的選擇會保留；沒有 instance 音訊欄位的照片按舊快門選擇補值，BGM 不會自動憑空開啟。既有非安插靜音影片 `dubWithBgm` 保持原邏輯，安插實例只由新設定控制。

## v0.72 Display Matrix 方向修正

- 影片方向先由 coded width/height 與 ffprobe Display Matrix 建立 canonical visual orientation，再進入 16:9／9:16 scale、crop、pad 或模糊背景。

## v0.69.0 Audio Processing

- 輸出頁新增 `Original Stereo 2.0`、`Enhanced Stereo 2.0`、`Virtual Surround 5.1` 與受限的「保持原始多聲道」。UI 不以未授權品牌名稱包裝一般 codec 或 Upmix。
- Enhanced Stereo 保持 2.0，Natural 預設只做保守 mid/side 寬度、輕微 EQ、LUFS 與 Peak Protection；不以強延遲製造容易相消的假寬度。
- Virtual 5.1 明確建立 `FL FR FC LFE SL SR`：Center 使用左右共同成分，Surround 使用差異成分與短延遲／頻帶限制，LFE 使用 L+R 並以 80–120 Hz low-pass；Natural 預設避免過強後方與低頻。
- 5.1 可選 AAC／AC-3／E-AC-3；YouTube 預設為 AAC 5.1、48 kHz、384 kbps。Virtual 5.1 是 Stereo 演算法模擬，不等同原生錄製 5.1。
- 完整畫面先沿用既有轉場、字幕、浮水印、BGM、無聲素材自動配樂與 Resume 流程；空間音訊隨後獨立處理，並用 `-c:v copy` 重新封裝，因此不會再次 Encode 已完成的影片 frames。
- A/B 試聽使用最多 20 秒的唯讀來源衍生 cache；Virtual 5.1 在雙聲道設備上提供明確標示的 5.1→Stereo 相容性監聽（不是 HRTF/binaural）。Meter 的 LUFS／Peak／Clipping 來自實際 FFmpeg ebur128/astats 分析，Virtual 另顯示實際 FL／FR／FC／LFE／SL／SR 六聲道 Peak。
- 「保持原始多聲道」第一版只開放單支原生多聲道影片的時間段輸出，以 video/audio stream copy 保留。多片段、轉場或混合 BGM 無法在不改變內容的前提下 bitstream preserve，會明確阻擋而不會靜默壓成立體聲。

- FFmpeg encoder／decoder 以短片真正啟動測試建立硬體／driver／FFmpeg fingerprint profile。不可用的 NVENC 不會被推薦或靜默改成 CPU；H.265 CPU 明示顯著較慢。

- Normal 由兩個工作起步並依 RAM／Commit／CPU／GPU／SSD／throughput 逐波測試 3、4；高速模式可由 profile 的三個工作起步。
- ETA 在 30 秒 warm-up 後用 FFmpeg `speed=x` EMA 平滑校正；監控新增 GPU Compute、VRAM 與 Current ETA。
- SSD 保留 1 GiB 防毀檔硬門檻，另以 `max(20 GiB, 磁碟容量 5%)` 做可確認後繼續的建議安全餘量。
- 完整決策見 `docs/adr/0060-runtime-probed-render-pipeline.md`；同專案短 benchmark 見 `docs/BENCHMARK_V067.json`。

- 每種字幕可獨立設定上／中／下位置與文字大小；長句會依輸出寬度自動換行，同位置雙語會自動分層。

## 目前功能

- 選擇單一或多個影片／照片，或選擇來源資料夾；白名單包含 JPG／JPEG／PNG／HEIC／HEIF 與 MOV 等常見格式，副檔名不分大小寫。
- 依智慧順序、自然檔名、拍攝／檔案時間或加入順序排列。
- 顯示縮圖、類型、大小、時間、影片時長與基本規格；網格隱藏重複來源路徑，切換清單檢視仍可查看完整路徑。
- 圖片放大；影片以低解析代理播放、暫停及拖曳。放大影片依 ffprobe display dimensions／rotation 維持 16:9、9:16 等原始顯示比例，控制列位於畫面外，不遮住影像。
- 網格內可直接播放／暫停每支影片的代理預覽，不必先打開大視窗。
- 網格影片縮圖上原本的「點擊放大」區域，左鍵會直接依副檔名播放器設定開啟唯讀意圖原檔，不再先開 App 放大視窗；照片縮圖仍在 App 內等比例放大，網格播放及其他控制不變。
- 每支影片預覽下方有同一條雙把手 IN／OUT bar；設定保存於 App manifest，不寫入來源 metadata。
- 依目前排序連續播放全部素材，不產生檔案。
- 照片加入時預設顯示 5 秒，每張可在網格調整為 3、4、5、6 或 7 秒；設定會保存並用於總體預覽、時間線及串連 MP4。
- 每張照片預設啟用草漯沙丘前案已採用的 Camera Shutter Click（輸出增益 70%），可在照片卡片逐張關閉；總體預覽與實際串連 MP4 都會依設定播放。
- 每張影片卡可把已排入正片的照片或其他影片安插在指定來源時間；App 只在 manifest 記錄安插點，輸出時非破壞性展開為主影片前段／安插素材／主影片後段，素材不會在正片重複播放。
- 安插視窗可依來源資料夾篩選素材，也可直接開啟 Windows 資料夾選擇器加入另一個資料夾；新加入素材會先留在「待決定」，確認安插前不會自動混入正片。
- 插入影片有獨立雙把手 IN／OUT，可縮短或重新放寬到來源有效範圍；同一安插時間可接續多張照片／影片，並以「接前／接後」調整播放次序。
- 素材安插點必須在主影片目前保留範圍內，並距保留段兩端至少 0.75 秒；取消安插後，素材會回到安插前的正片順位。
- 安插、排除、片段與音量區段的開始／結束使用獨立「分」「秒」輸入格；按 Enter 會由起點分鐘依序前進，manifest 內仍保存整數毫秒，維持輸出精度。
- 照片點擊放大後依 display dimensions／rotation 維持 16:9、9:16 等原始比例，以 `contain` 完整顯示，不裁切或拉伸。
- 依目前排序串連所有影片與照片；每個交接可選 0.3／0.5／0.7 秒影像疊化與音訊淡化，直式照片沿用中央等比＋同源模糊背景。
- 串連預覽可選 360p、480p、720p、1080p（1920×1080）、1440p／2K（2560×1440）或 4K；新安裝預設 1080p。Shorts 可選 1080×1920 或 1440×2560，皆依同一 Canvas 規格等比構圖。
- 「AI 精彩片頭建議」先以本機亮度、色彩與幀間變化建立少量來源可追溯候選；設定具可用額度的 OpenAI API 後，再以短音訊與低解析三格故事板優先比對人物、事件、故事脈絡與地點，最後才參考本機動態／色彩分數重新排序。
- 沒有完整故事背景或 API 憑證時，片頭會明確顯示原因並退回本機候選；AI 不以臉孔外觀猜測真實身分，也不把不確定地點當成事實。
- 每個片頭建議均可依素材經 rotation 修正後的原始顯示比例完整預覽，不裁切或拉伸；並可調整 IN／OUT、上移、下移或排除，再輸出 360p／480p／720p／4K Intro 預覽。App 不再限制片頭總長為 3 分鐘；超過時只顯示紅色警示。最多 50 段、每段至少 3 秒且最多 22 秒，AI 建議、人工修改與輸出共用同一驗證規則。
- 片頭預覽可選「整體循環」或「單段循環」；預設整體循環會按目前順位逐段播放，最後一段結束後再回第一段，按暫停即停止推進。
- 片頭片段標題列可直接用滑鼠拖曳重排，順位會即時變動並在放開後保存；往前／往後按鈕仍可使用。
- 產出頁會自動沿用上次輸出資料夾並準備不覆寫的 MP4 檔名；需要變更時仍可用 Windows 原生儲存視窗另行指定。按「OK，開始產出」才執行，可查看進度與取消。取消時會先要求 FFmpeg 安全寫完 MPEG-4 結尾，若已產生足夠畫面便保留較短、可播放的 MP4；若取消得太早而無法形成有效媒體，才清理 App 自己的 partial 並明確提示。
- 正片輸出頁預設勾選「自動串接已確認片頭＋正片」；片頭依目前確認順序放在正片之前，也可取消勾選而只產出正片。Main process 會再次核對片頭與正片片段，不能用過期的畫面清單輸出。
- 正片成功產出後預設倒數 60 秒開啟 YouTube 最後確認頁；使用者可在輸出前取消勾選，或在倒數中按取消。取消只停止上傳準備，已完成的本機 MP4 仍完整保留；倒數不會跳過頻道、標題、兒童內容、隱私與人工確認。
- 程式上方「預覽檔案庫」會持久保存 App 產出的正片、片頭與取消後有效短片，重開 App 後仍可播放、在檔案總管找出或投稿。舊版本已產生但未被登記的 MP4，可用原生多選視窗加入索引；移除歷史紀錄不會刪除磁碟檔。
- 網格／清單檢視。
- App 會保存上次使用的網格／清單、輸出解析度、疊化秒數、正片與 Intro 的 MP3 嵌入選擇、Intro 串接、輸出後上傳準備、YouTube 不公開／私人選擇及各類素材／專案／成品／字幕／配樂／播放器／OAuth 選檔資料夾；重開後直接沿用。兒童內容屬每支影片的合規確認，不會被自動沿用。
- 程式上方「Aa 設定」可調整全介面文字及 75%–150% 整體縮放，特別涵蓋網格卡片下方資訊；設定即時套用並在下次開啟時恢復，也可用 `Ctrl`＋滑鼠滾輪或鍵盤快捷鍵縮放。
- 程式上方顯示目前版本，並提供畫面上的上一步／下一步按鈕以及 `Ctrl+Z`／`Ctrl+Y`（另支援 `Ctrl+Shift+Z`）；最多保留目前工作階段 50 個專案資料變更，來源檔永遠不列入復原操作。
- 每張素材卡可「從正片移除」；安全確認會列出影響，且預設焦點在取消。此動作只移除正片／待決定引用，絕不刪除磁碟來源、proxy 或 metadata。
- 最近移除區與操作後提示均可一鍵恢復；原順序、安插紀錄、音量與正片排除設定完整保留，重開 App 後仍可恢復。
- Intro 與 Main 引用獨立；每個 Intro segment 可單獨移除／恢復，同來源其他片段與正片不受影響，重新分析也不會自動復活手動排除片段。
- 自動保存最小 project/source manifest，重新開啟後恢復。
- 左上角「檔案」選單可儲存、另存命名 `.swproj` 專案或開啟舊專案；專案檔包含素材引用、順序、IN／OUT、照片時長、排除區段、Intro、音量、BGM、故事背景與字幕，但不複製媒體、cache 或 API Key。
- 衍生縮圖與預覽只放在 Electron 的 App Data cache。
- 「播放設定」提供全域預設及依副檔名覆寫；內建支援 Windows 系統預設、VLC、Windows Media Player、MPC-HC，也可瀏覽選擇其他 `.exe`。
- `.mp4`、`.mov` 已有獨立路由列，並可新增 `.mkv` 等其他支援副檔名；比對不分大小寫。
- 網格影片卡的「以外部播放器開啟」左鍵會立即依副檔名路由開啟唯讀意圖原檔；右鍵、鍵盤選單鍵或 `Shift+F10` 才開啟 proxy／原檔選擇視窗。第三方播放器的實際寫入行為不受 App 控制；放大預覽頁仍以明確選項視窗開啟。
- 指定播放器遺失或啟動失敗時會降級至 Windows 系統預設；再失敗則提示回到 App 內建 proxy，不會卡住 UI。
- 每張影片卡可建立多個不重疊的「音量區段」；範圍限制在目前 IN／OUT，音量固定 0%–300%。新專案素材原音預設為 100%，既有 manifest 的有效 80% 等數值會保留；未另外指定的區段使用專案預設。片段、音量或安插已有設定時，卡片按鈕會以不同高對比顏色顯示。
- 放大影片預覽提供可拖曳／點選的 10 ms 播放頭、毫秒時間顯示與穩定播放／暫停；可直接把目前播放位置設為正片排除區段的起點或終點。
- 每支影片可建立多個非破壞性「正片排除區段」；開始／結束限制於 IN／OUT，保存時自動排序並合併重疊或相鄰區段，也可單筆刪除或一鍵清除。
- 正片輸出會把 IN／OUT 扣除排除範圍後展開成連續保留子片段，不插入黑畫面或靜音占位；音量 automation、轉場、直式模糊、BGM 與字幕時間基準都使用實際保留片段。
- 全部有效範圍被排除的素材仍留在網格與來源 manifest，但不參與正片輸出；正片無保留片段時輸出按鈕安全停用。Intro 不受 Main 排除範圍影響。
- IN／OUT 縮短時，超出範圍的音量區段會安全裁切或移除，並在卡片顯示實際調整筆數。
- 補充匯入的素材逐一詢問放在最前、最後、指定素材前／後或待決定區；待決定素材不進入串連輸出。
- 網格卡片可用滑鼠左鍵長按後任意拖曳前後順序；拖動時 01、02…序號即時更新，放開後保存為 `timelineOrder`。上移／下移按鈕仍保留供鍵盤與精確操作，Main process 在輸出前再次核對。
- 9:16 素材會結合 ffprobe display rotation 判斷方向；16:9 輸出保持中央等比前景，左右使用同來源放大模糊填滿。
- 可加入一首或多首唯讀 MP3 配樂，設定 timeline、source IN／OUT、淡入淡出、順序及 0%–300% 音量；BGM 預設為 35%。多首曲目可依清單連續排列，並套用於正片與 Intro。
- 可混合加入多個 YouTube 連結作為來源／權利待確認參考，但 App 不會任意把 YouTube 影片轉下載成 MP3；每筆連結必須由使用者確認具使用權，再指定自有、已授權或透過 YouTube Audio Library 正式下載的本機 MP3 才能輸出。待確認或離線項目會安全阻擋輸出。
- 串連與 Intro 會混合片段原音和 BGM，最後套用 0.95 peak limiter；300% 是數位增益上限，不代表主觀響度三倍，也不保證無失真素材能被修復。
- AI 字幕預設直接用低解析故事板與專案主題／地點／故事背景建立知識型介紹，內容可涵蓋畫面直接相關的地方特色、歷史文化、自然生態、森林養護與環境保護；語音轉錄／說話者分段預設關閉，只有勾選「同時分析素材語音」才執行。
- 字幕頁採類 YouTube Studio 的逐項審核：同步 proxy 影像、時間、文字、說話者、畫面／事件／人物／地點證據、相關分數與警告均可核對；草稿可修改、確認或排除。
- 只有已確認 cue 能透過原生儲存視窗原子匯出 UTF-8 `.srt`；AI 草稿不會自動發布或輸出。
- 影片順序或 IN／OUT 改變後，字幕會標記需要複核；逐項確認並保存後，可在串連輸出永久嵌入一至兩種字幕。可選繁中、英文、簡中、日文、韓文，並分別設定位置、字級與自動換行。
- 「AI 帳號／故事」設定可保存多個 OpenAI API profile 並切換；API Key 由 Electron `safeStorage` 使用 Windows OS 加密並與專案分離。知識型字幕在 API 不可用時可透過本機 Codex 執行程式安全使用 ChatGPT 登入；App 不讀取或複製憑證。語音辨識與字幕翻譯仍不共用此備援。
- 故事背景的主題、人物、地點、故事／劇本／特色說明與觀眾承諾都有麥克風輸入；預設繁體中文、可切換英文。單次最多 120 秒／25 MB，辨識完成後不保存錄音檔；也可隨時用 Windows `Win+H` 輸入。
- OpenAI 429 錯誤會分開顯示 API project 額度／支出上限或暫時速率限制，並保留安全的錯誤代碼與 Request ID，不再把所有情況合併成同一句話。
- 非繁中字幕先以目前 OpenAI API profile 發出 `store: false` 的全新 Responses 請求；失敗時才用另行設定、Windows 加密保存的 Google Cloud Translation Basic v2 API Key。這不是 ChatGPT 網頁對話，也不能沿用 Codex 登入額度或 YouTube OAuth 憑證。
- 預設視覺模型為 `gpt-5.6-terra`，轉錄模型為 `gpt-4o-transcribe-diarize`；知識型字幕啟用 OpenAI API 與 Codex／ChatGPT 登入兩條實際路徑，其他 AI 仍只保留未啟用的擴充方向。
- schema 1–12 manifest 會自動遷移到 schema 13；舊照片安插資料會轉為通用素材安插，既有通用安插會補上來源位置，並保留照片時間、快門聲、字幕、音量、片頭與既有編輯欄位。未知或損壞 schema 會停止且不取代目前專案。
- 完成或取消後安全保留的 MP4 可直接依 `.mp4` 外部播放器設定播放。完成的正片串連預覽可透過使用者自己的 Google Desktop OAuth client 上傳至核對過的 YouTube 頻道，預設不公開、可改私人。
- 「平台上傳設定」會顯示 YouTube 的實際連結狀態、頻道名稱與頻道 ID。登入使用 Google 官方 OAuth 網頁；App 不提供帳號密碼欄位，也不讀取、顯示或保存 Google／YouTube 密碼，只保存 Windows 加密的授權 token。
- BiliBili／TikTok 採官方投稿頁安全交接：App 會複製完成檔路徑、在檔案總管選取 MP4 並開啟官方投稿頁；使用者仍需在平台內登入並確認標題、分區／隱私、版權及最後發布。未取得平台開發者應用與核准 scope 前，不假裝已完成自動 API 發布。

npm run package:win

## 資料位置與安全

專案 manifest、一般使用偏好、最近使用資料夾、preview cache、預覽成品索引、Intro／AI story analysis cache、AI provider 設定、YouTube 設定與外部播放器設定放在 Electron `userData` 目錄，而不是來源資料夾。麥克風短錄音直接在記憶體中送出辨識，不落盤為永久錄音。AI API Key、YouTube OAuth client secret 與 refresh token 另存為 OS 加密檔，不會進 `.swproj`、renderer、一般偏好、預覽成品索引或分析結果；平台帳號密碼始終只輸入官方登入頁。AI 呼叫只上傳本次候選的短音訊、低解析故事板與使用者填寫的故事背景，不上傳完整原始影片；`store:false`，但實際 API 資料治理仍依帳號與 OpenAI API 政策。使用者另存的 `.swproj` 也採同資料夾唯一 partial＋可恢復替換，只有原生儲存／開啟視窗選定的路徑可讀寫。Renderer 不取得 Node 或任意檔案系統權限；只能透過白名單 IPC 操作資產 ID 或持久化的預覽 job ID。MP3 路徑只能由原生選擇視窗加入，後續 IPC 不能改寫成任意路徑；YouTube 參考連結不會觸發任意下載。外部播放 IPC 也只接受資產 ID 與 `PROXY`／`ORIGINAL`；預覽檔案庫只登記 App 實際產出或使用者用原生視窗明確選取的 MP4，Main process 會在播放或投稿前重新驗證絕對路徑、存在性與檔案類型。從預覽庫移除只刪除索引項目，不會刪除 MP4。素材安插只保存 asset ID、時間、插入影片 IN／OUT 與原順位，不改寫來源。封裝時只有 SHA-256 符合既定值的沙丘快門聲會被複製到 App 自有資源，並附來源與授權紀錄。MP4、SRT 與 AI 設定同樣先寫唯一 partial；一般成功後才完成，使用者取消 MP4 時則以 FFmpeg 的安全結束與 ffprobe 驗證決定是否保留較短成品。Preview 永遠是衍生檔，不能作正式 Master 來源。
